# AI 脚本与 Prompt

本目录提供两类东西：**能直接跑的脚本**（4 个，纯标准库、零第三方依赖），
以及**能把脚本重新生成出来的提示词**（Prompt）。两者是同一套规则的两个形态：
脚本是规则的固化结果，Prompt 是规则的文字形态。

---

## 一、脚本清单

| 文件 | 作用 | 用法 |
|---|---|---|
| `batch_rename.py` | **主体脚本**。给一个收件夹，把票据原地改名为 `YYYYMMDD_类别_金额.txt`，非票据不动，已是标准名则跳过 | `python batch_rename.py <收件夹路径> --log <日志目录>` |
| `make_samples.py` | 样本生成器。按固定种子（20260900 + 组号）生成 10 组 × 12 份样本与标准答案，重跑结果完全一致 | `python make_samples.py` |
| `run_timing.py` | AI 组计时。每组跑 3 轮，端到端计时（含解释器启动），输出每组中位数 | `python run_timing.py` |
| `verify.py` | 正确性核验。把处理后的实际文件名与标准答案逐份比对，输出正确数/错误明细 | `python verify.py` |

### 运行环境

- Python 3.9 及以上（实测 3.13），无需 `pip install` 任何东西。
- Windows / macOS / Linux 均可，路径用 `pathlib` 处理。

### 快速试跑

```bash
# 1. 拿一组样本试跑（对应校验规则第 7 条：小样本先跑）
python batch_rename.py "01_任务样本/样本原始文件/sample-01" --log ./log

# 2. 看结果：目录里应出现 10 个 2026xxxx_类别_金额.txt，
#    README.txt 与 扫描失败_空白页.txt 必须还是原名
# 3. 再跑一次，改名数应为 0（幂等性）
python batch_rename.py "01_任务样本/样本原始文件/sample-01" --log ./log
```

## 二、`batch_rename.py` 的四个关键处理点

| 处理点 | 解决的问题 | 做法 |
|---|---|---|
| **编码兜底** | 扫描件有的是 UTF-8 带 BOM，有的是 GBK | 按 `utf-8-sig` → `gbk` 依次尝试解码 |
| **文本归一化** | 全角空格、全角冒号、全角逗号、CRLF 干扰正则 | 统一转为半角后再匹配 |
| **两级日期解析** | 日期有 `2026/10/29`、`2026-10-29`、`2026年10月29日`、`20260923` 四种写法 | 先匹配带分隔符的写法，再兜底 8 位连写 |
| **三项齐全才改名** | 非票据文件不能被误改 | 日期、类别、金额缺一即保持原名不动 |

另外两条保障：已是标准名的文件直接跳过（幂等）；撞名时追加序号、绝不覆盖。

## 三、Prompt：把规则交给 AI 的写法

以下提示词可直接复制使用。它的要点不是"帮我写个脚本"，而是**把判据写死**——
字段位置、命名格式、边界情形、验收标准，全部前置约定，AI 才可能一次成型。

```text
你是我的批处理脚本助手。请用 Python 写一个单文件脚本 batch_rename.py，
只用标准库，不引入任何第三方依赖。

【任务】
给定一个收件夹，其中每个文件要么是票据，要么不是。
对票据：读取文件内容中的日期、类别、金额三项，把文件名改为
    YYYYMMDD_类别_金额.txt
原地改名，不新建文件夹、不移动文件、不删除文件。

【字段规则】
- 日期：可能写成 2026/10/29、2026-10-29、2026年10月29日、20260923，
  统一输出 8 位，月份和日补零。
- 类别：只可能是 餐饮 / 交通 / 办公 / 住宿 / 其他 之一，原样照抄。
- 金额：可能写成 ¥111.60、111.6 元、价税合计 368.21 元，
  统一输出保留两位小数、不带货币符号。
- 三项中任何一项读不出来，就视为非票据，保持原名不动，不要猜。

【边界处理】
1. 文件编码可能是 UTF-8（带或不带 BOM）或 GBK，请依次尝试解码。
2. 内容里可能有全角空格、全角冒号、全角逗号、CRLF 换行，匹配前先归一化。
3. 已经是标准名的文件直接跳过，保证重复运行不产生任何变化（幂等）。
4. 目标文件名已存在时，追加 _2、_3 序号，绝不覆盖原文件。
5. 后缀 .txt 与 .TXT 都算合法，大小写不计错。

【输出】
- 处理完成后在日志目录写 manifest.csv，逐文件记录：
  原文件名、新文件名、解析出的 日期/类别/金额、处理状态（renamed / untouched / skipped / conflict）。
- 终端打印一行汇总：改了多少、没动多少、跳过多少、冲突多少。

【自检】
写完后请自己构造 2 个反例验证：一份没有金额的文件必须不被改名；
同一目录连续跑两次，第二次改名数必须为 0。
```

### 为什么这样写

| 提示词里的约束 | 对应的失效场景 |
|---|---|
| "三项中任何一项读不出来就保持原名，不要猜" | AI 最爱补全缺失字段，猜错比不改更糟 |
| "不新建文件夹、不移动文件" | 不说清楚，AI 默认会帮你"整理"成月份目录 |
| "已是标准名直接跳过" | 不写这条，重跑会生成 `_2` 后缀的重复文件 |
| "绝不覆盖" | 撞名时静默覆盖会直接丢原件 |
| "自己构造 2 个反例验证" | 让 AI 先自证，比事后人工排查便宜得多 |

## 四、脚本与校验规则的对应

| 校验规则 | 脚本中的落点 |
|---|---|
| 1 全量比对 | `verify.py` 逐文件比对标准答案 |
| 2 数量守恒 | `manifest.csv` 四类状态计数之和 = 12 |
| 3 反向校验 | 三项缺一 → `untouched`，不改名 |
| 4 幂等性 | `RE_STD_NAME.match(f.name)` 命中即 `skipped` |
| 5 不覆盖 | `if (src / new_name).exists():` 加序号 |
| 6 可追溯 | `manifest.csv` 逐行记录原文件名与去向 |
| 7 小样本先跑 | 使用说明中的"快速试跑"流程 |

规则全文见 `../04_人机校验规则/人机校验规则.md`。
