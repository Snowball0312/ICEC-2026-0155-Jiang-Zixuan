# 盲测录屏脚本（一镜到底，3–5 分钟）

> 评分第 ③ 项要的是"证据"。所谓证据，是**他人设工况、操作者不知情、当场跑出结果**。
> 因此录屏必须包含：设置工况 → 录音 → 命令运行 → 屏幕出结论，中间不剪辑。

> **本次执行方式的如实说明**：现场无第二人配合，11-22 的 7 段均由操作者本人设置、本人录音，
> 只有"录音时不看分析结果"这一点接近盲测。因此这 7 段**不构成**"他人设工况"的证据，只作流程演示
> 与标注校验；报告 13.1 节的 83.3% 已据此降级，泛化证据取自按轮分组交叉验证（99.86% / 100%）。
> 若后续有条件，请按下面第二节的流程重录一遍，由同学设置工况，即可补上这一项。

## 二、录制前 10 分钟检查（复现时按此清单）

1. 模型已训练：`03_特征与模型/model.json` 存在；把 `训练摘要.md` 里的三个数字记下来（口播用）——整段准确率、宏平均 F1、同档位遮挡判别准确率（见 `cv_同档遮挡.csv`）。
2. 终端字号调到 18–20，深色背景、浅色前景，保证录屏能看清结论行。
3. 录音直接存 `05_盲测与抗噪/现场录音/`。
4. 关闭系统通知、微信弹窗。
5. 请同学（不看屏幕）在纸上写好随机工况顺序，例如 L3 → L1 → L4 → L2（只测四种遮挡态）。
6. **L0 正常态不参加盲测。** 它只有 2 段且跨两个档位，只作基准对照，不进四分类器。

## 四、命令清单（可提前贴在记事本里，录制时直接复制）

```bash
cd 04_分析脚本

# 单段盲测（最常用）
python predict.py ../05_盲测与抗噪/现场录音/盲测01.wav

# 带逐窗明细，便于现场展示"证据链"
python predict.py ../05_盲测与抗噪/现场录音/盲测01.wav --detail ../03_特征与模型/盲测01逐窗明细.csv

# 抗噪演示：把同一段降到 0 dB SNR 再诊断
python predict.py ../05_盲测与抗噪/现场录音/盲测01.wav --noise-snr 0
```

## 五、判错时的三种补救（提前想好，不要慌）

1. **先报置信度**："置信度只有 41%，脚本已经提示结论存疑"——说明系统有自知之明，是设计特性而非事后辩解。
2. **延长录音**：现场再录 60 s 重跑，说明增加投票窗数可提升稳定性。
3. **给出混淆原因**：例如 L1（一档半遮挡）被判成 L2（一档全遮挡），可说"两者转速差 62%（677 对 1090 Hz），谱形差得更明显——半遮挡平坦度 0.012、全遮挡 0.030，2–8 kHz 占比 0.17 对 0.27，纸片贴缝一变就会跨过边界"；若是在两个半遮挡类之间判错（L1→L3，如盲测01 的 708 Hz），则说明"半遮挡的摩擦制动把两个档位压到一起，708 距两类中心只差 +5.8% / −5.2%，这一类本质上不可分"——这正是报告 10.4 节写明的边界。

## 八、录制方式（最省事的做法）

**用手机拍桌面全景，一镜到底**：手机支在书堆上，画面同时框住风扇与电脑屏幕，
从"抽签 → 装遮挡 → 录 20 秒 → 跑命令 → 出结论 → 揭晓"全程不停止录制。
无需录屏软件，无需剪辑；终端字号提前调到 18–20，保证画面中能看清结论行。
